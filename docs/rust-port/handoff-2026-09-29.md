## 목표와 확정 제약

원본 Windows 작업 표시줄 오버레이를 Rust로 포팅하고 OpenCode Go 사용량 표시를 추가한다. 사용자는 개발 및 실행 환경에 .NET을 포함하지 않기를 원한다. 원본 C# 앱이나 `dotnet`은 실행하지 않는다. 검증은 Rust/Cargo와 Windows 네이티브 실행으로 수행한다. 사용자가 직접 실행 검증을 맡는 방식은 요청하지 말고 가능한 검증을 작업자가 수행한다.

원본 저장소에 PR을 만든 상태가 아니다. 변경은 개인 포크의 `rust/phase-0` 브랜치에 올라가 있다. 포크의 `main`/원본 저장소에 임의로 병합하거나 PR을 만들지 않는다.

## 현재 범위 및 상태

계획은 Phase 0–8, 총 9개 Phase와 63개 phase-level task(P0 5개, P1 7개, P2 8개, P3 8개, P4 5개, P5 9개, P6 7개, P7 4개, P8 10개)다. **닫힌 Phase는 Phase 0 하나**다. 나머지 8개 Phase, 58개 task는 완료 기준이 닫히지 않았다. 일부 구현이 있어도 Windows 동작 검증이나 수용 기준이 실패/미수행이면 완료로 세지 않는다.

| 영역 | 구현 현황 | 닫히지 않은 주요 기준 |
|---|---|---|
| Phase 0 기획/기준선 | 완료. 원본 기능 카탈로그 35개, 함수 I/O 계약, traceability, ADR 작성 | 없음 |
| Phase 1 Win32 PoT | Layered HWND, BGRA 출력, 컨텍스트 메뉴, Settings 창, 위치/잠금/snap, DPI 메시지 처리 구현 | 최신 Windows smoke가 드래그 동작에서 실패. Windows 11, 실제 다중 모니터/DPI 검증 미완료. 렌더러/설정 UI 결정도 PoT 수용 기준으로 종결 필요 |
| Phase 2 앱/설정 | 버전 설정, Rust 전용 저장 경로, startup 등록, 단일 인스턴스, 설정 컨트롤 일부 구현 | 전체 설정 탐색/대시보드, reset, 모든 lifecycle·migration·persistence 수용 검증 미완료 |
| Phase 3 CPU/RAM/네트워크/디스크 | CPU/RAM/집계 네트워크, 디스크 용량 표본 구현 | 네트워크 선택·필터 의미, per-drive 활동/선택, 원본과 같은 집계/단위 경계 및 Windows 비교 미완료 |
| Phase 4 GPU | 공급자 일부 구조 외 실측 공급자 미완료 | NVIDIA, AMD, Windows fallback, 온도 및 장치별 검증 |
| Phase 5 UI/렌더링 | 일부 metric 표시/Compact, OpenCode/Codex 세그먼트, taskbar snap/free, fullscreen 단순 감지 구현 | 다중 모니터 fullscreen, fade/debounce, 전체 색상/테마/폰트/크기/간격/캡슐, 메뉴 parity 미완료 |
| Phase 6 통합/수용 | Rust CI와 hosted Windows smoke harness 존재 | 현재 smoke 실패 해결, Windows 11·하드웨어에서 catalog 항목별 증거, failure/soak 검증 및 traceability 종결 |
| Phase 7 패키징 | Rust 실행 파일과 LICENSE/README가 든 휴대용 디렉터리 생성 및 CI artifact 업로드 | ZIP/checksum, 설치·업데이트·제거·프로필 복원 테스트, 개인 배포 자료 미완료 |
| Phase 8 AI 사용량 | OpenCode Go 키 DPAPI 저장, 폴링·overlay/settings, Codex 읽기 전용 파서/폴링, DeepSeek balance API 파서 구현 | DeepSeek 키/UI 연결, provider별 통합/보안 검증, Zen 잔액(선택) 미완료 |

현재 표시 기본은 잔량(remaining %)이다(`ai_show_used_percent=false`). Codex 선택 UI도 있다. Zen 크레딧은 구현하지 않았다. 1차 우선순위는 여전히 OpenCode Go다.

## 검증 현황

최신 GitHub Actions 실행은 [run 36508140077](https://github.com/thdrmsqhd/kil0bit-system-monitor/actions/runs/36508140077), 커밋 `660e6b5f223c925e8b43bdcf221bd12ab6b5598f`다.

| 검사 | 결과 | 의미 |
|---|---|---|
| `cargo fmt --all -- --check` | 통과 | 현재 Rust 코드 형식 검사 |
| `cargo clippy --workspace --all-targets -- -D warnings` | 통과 | 경고를 오류로 취급한 정적 검사 |
| `cargo test --workspace` | 통과 | 현재 단위/통합 테스트. 원본 기능 전체 수용을 뜻하지 않음 |
| x64 MSVC release build | 통과 | Windows 실행 파일 링크 성공 |
| Rust 전용 휴대용 디렉터리 생성 및 업로드 | 통과 | artifact `kil0bit-system-monitor-rust-port` 생성 |
| Win32 layered-window smoke | **실패** | 오버레이는 실행됐으나 unlock 후 실제 드래그에서 좌표가 `(100,100) → (100,100)`으로 그대로임 |

Smoke 시험은 test 전용 APPDATA 프로필을 쓰고 fullscreen 숨김을 비활성화한다. 잠금 해제 상태와 오버레이 hit-test 위치를 확인하며 `SendInput` 마우스 이동도 보냈지만, 최신 실행에서도 창이 이동하지 않았다. 이 검증을 억지로 통과 처리하거나 테스트 조건을 제거하지 않는다. 먼저 실제 마우스 메시지와 HWND 이동 경로를 계측해 원인을 찾는다. 실패한 이전 실행도 run 36507690404, 36507215586에 남아 있다.

이 검증은 GitHub `windows-2022`의 Windows Server 2022에서 이뤄졌다. Windows 11, 실제 사용자 세션/다중 모니터, GPU vendor별 동작은 아직 확인하지 않았다. workflow는 Rust만 호출했고 이 프로젝트 작업에서 .NET 앱/`dotnet`을 실행하지 않았다. 다만 GitHub hosted runner 이미지 자체가 .NET이 아예 없는 환경이라는 주장은 할 수 없다. **RUNTIME_DIFF_NOT_RUN**은 원본 실행을 금지한 정책에 따른 고정 제한이다.

현재 실행 환경에는 Cargo가 없어 로컬 `cargo` 검증을 할 수 없었다. CI가 형식·Clippy·테스트·MSVC 빌드·패키지 생성 게이트를 대신 확인했으나 GUI smoke 실패는 남아 있다.

## 다음 작업 순서

1. Win32 smoke 드래그 실패를 재현하고 원인을 계측한다. 다음 실행에서 잠금 상태, 커서 이동, 실제 클릭 위치는 이미 체크한다. `WM_NCHITTEST`/마우스 메시지 수신과 `WM_MOVE`/`GetWindowRect` 변화를 함께 구분해 확인한다. 원인 수정 후 CI smoke가 실제로 통과해야 Phase 1 동작 게이트를 다시 평가할 수 있다.
2. UI 설정 창을 닫고 오버레이를 움직이는 사용자 흐름을 Windows Server에서 안정적으로 자동화한다. 이후 가능한 경우 Windows 11 환경을 별도로 확보해 상호작용과 DPI를 검사한다. Windows Server 결과를 Windows 11 증거로 쓰지 않는다.
3. Phase 2의 설정·reset·저장·기동 흐름 수용 테스트를 닫고, Phase 3 per-drive/network 선택 및 디스크 활동을 구현한다.
4. NVIDIA/AMD/WDDM 기능은 실제 해당 장치가 없으면 구현 및 정적 검사와 `BLOCKED` 실기기 검증을 분리한다. 하드웨어가 없는데 `RUN_PASS`라고 쓰지 않는다.
5. Phase 5 원본 카탈로그에 맞춘 표시/테마/레이아웃과 멀티 모니터 동작을 완성한다.
6. Phase 6에서 35개 원본 기능 ID와 AIU 확장 ID 각각에 구현, 테스트, Windows 실행 증거를 연결한다. 원본 앱은 실행하지 않고 `RUNTIME_DIFF_NOT_RUN`을 유지한다.
7. 패키지를 ZIP/checksum/업그레이드 및 제거 검증까지 확장하고 Phase 7을 닫는다. Phase 8의 DeepSeek/Zen 선택 범위와 AI provider 통합을 정리한다.

Phase를 닫을 때는 `task-breakdown.md`, `traceability.md`, `original-feature-catalog.md`의 세 상태를 같이 갱신한다. 구현됐다는 이유만으로 수용 검증을 `RUN_PASS`로 바꾸지 않는다.
