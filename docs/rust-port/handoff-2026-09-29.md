## 후속 작업 기록

### 2026-10-13 — CI 정책 변경 (Windows 러너 분 절약)

- `.github/workflows/rust.yml`에서 **Win32 layered-window smoke 스텝을 제거**했다.
- 이유: `windows-2022` 헤드리스 세션에서 `SendInput` 기반 드래그가 안정적으로 동작하지 않았고, 9/29 하루 `rust/phase-0` 기준 실패 런이 60회 이상 누적되며 러너 분을 소모했다.
- CI에 남는 것: `cargo fmt`, Clippy (`-D warnings`), `cargo test`, MSVC release build, 포터블 디렉터리/ZIP/SHA256 artifact 업로드.
- GUI 수용(드래그, 잠금, 스냅, 멀티 모니터, DPI, 메뉴/Settings 상호작용)은 [`evidence/p1-windows-run-checklist.md`](evidence/p1-windows-run-checklist.md)의 **Windows 11 로컬 체크리스트**로만 수행한다.
- `overlay-smoke.exe` 바이너리와 소스는 유지한다. 로컬에서 선택적으로 실행할 수 있으나 **CI 게이트가 아니다**.
- Phase 1 드래그 게이트를 CI 통과로 닫지 않는다. 로컬 Windows 11에서 체크리스트 4–6항이 통과하면 그때 Phase 1 동작 증거를 갱신한다.

### 2026-09-29 — 코드 우선 진행 (스냅샷)

- Win32 오버레이 드래그: `HTCAPTION` 기본 창 이동으로 전환 후에도 Server 2022 smoke에서는 이동하지 않음. `SendInput` 후 `WM_NCLBUTTONDOWN`/`WM_LBUTTONDOWN`/`WM_MOUSEMOVE` 수신 0건. **당시 드래그 게이트 실패**.
- 설정: 전체 초기화, 기존 설정 가져오기, 백업 복원 후 위치·스냅·항상 위·표시 여부와 AI 작업자를 실행 중인 창에 다시 적용.
- 모니터링: 네트워크 목록/수집 동일 필터, 사용자 가상 어댑터 유지, GPU `phys_N` 번호 비교, Settings GPU 공급자/번호 선택 저장. **실제 GPU 이름·LUID 매핑과 벤더 하드웨어 검증은 남아 있음.**
- 화면: 잠금 해제 캡션 우클릭 메뉴, 전체 화면 숨김은 동일 모니터 전면 창에만 적용.

남은 구현 우선순위: GPU 장치 이름/LUID 선택 매핑, Settings 전체 동작 수용, 디스크/네트워크 원본 규칙 추가 대조, Windows 11·실기기 검증.

## 목표와 확정 제약

원본 Windows 작업 표시줄 오버레이를 Rust로 포팅하고 OpenCode Go 사용량 표시를 추가한다. 사용자는 개발 및 실행 환경에 .NET을 포함하지 않기를 원한다. 원본 C# 앱이나 `dotnet`은 실행하지 않는다. 검증은 Rust/Cargo와 Windows 네이티브 실행으로 수행한다.

원본 저장소에 PR을 만든 상태가 아니다. 변경은 개인 포크의 `rust/phase-0` 브랜치에 올라가 있다. 포크의 `main`/원본 저장소에 임의로 병합하거나 PR을 만들지 않는다.

## 현재 범위 및 상태

계획은 Phase 0–8, 총 9개 Phase와 63개 phase-level task다. **닫힌 Phase는 Phase 0 하나**다. 나머지 8개 Phase는 완료 기준이 닫히지 않았다. 일부 구현이 있어도 Windows 동작 검증이나 수용 기준이 실패/미수행이면 완료로 세지 않는다.

| 영역 | 구현 현황 | 닫히지 않은 주요 기준 |
|---|---|---|
| Phase 0 기획/기준선 | 완료 | 없음 |
| Phase 1 Win32 PoT | Layered HWND, BGRA, 메뉴, Settings, 위치/잠금/snap, DPI 구현 | **CI smoke 제거됨.** 드래그·멀티 모니터·DPI는 Windows 11 로컬 체크리스트 대기. |
| Phase 2 앱/설정 | 버전 설정, Rust 경로, startup, 단일 인스턴스, 설정 컨트롤 일부 | 전체 설정 탐색/대시보드, reset, lifecycle·migration·persistence 수용 검증 |
| Phase 3 CPU/RAM/네트워크/디스크 | CPU/RAM/네트워크, 디스크 용량·활동 표본 | 네트워크 선택·필터, per-drive 선택, 원본 단위 경계 Windows 비교 |
| Phase 4 GPU | NVIDIA/AMD/D3DKMT 샘플 경로 존재 | 장치 이름·LUID 매핑, 벤더별 실기기 검증 |
| Phase 5 UI/렌더링 | metric 표시/Compact, AI 세그먼트, snap/free, fullscreen 단순 감지 | fade/debounce, 멀티 모니터, 전체 테마/폰트/레이아웃 |
| Phase 6 통합/수용 | CI(포맷·Clippy·테스트·빌드·패키지) | Windows 11 카탈로그 항목별 증거, soak, traceability |
| Phase 7 패키징 | 포터블 디렉터리 + CI artifact | ZIP/checksum 설치·업데이트·제거 검증 |
| Phase 8 AI 사용량 | OpenCode/Codex/DeepSeek 파서·폴링 | DeepSeek UI 연결, provider 통합 검증, Zen(선택) |

### 로컬 Windows 11 (수동)

[`evidence/p1-windows-run-checklist.md`](evidence/p1-windows-run-checklist.md)를 따른다. 드래그/잠금/스냅/Settings/DPI는 여기서만 `RUN_PASS`로 올릴 수 있다. Windows Server CI 결과를 Windows 11 증거로 쓰지 않는다.

**RUNTIME_DIFF_NOT_RUN**은 원본 실행 금지 정책에 따른 고정 제한이다.

## 다음 작업 순서

1. **Windows 11 로컬**에서 Phase 1 체크리스트(특히 드래그·잠금·스냅)를 실행하고 증거를 `evidence/`에 기록한다.
2. Phase 2 설정·reset·저장·기동 흐름 수용을 로컬에서 닫고, Phase 3 per-drive/network 선택·디스크 활동을 원본 규칙과 추가 대조한다.
3. GPU 장치 이름/LUID 선택 매핑을 구현한다. NVIDIA/AMD/WDDM은 해당 하드웨어가 없으면 구현·정적 검사와 `BLOCKED` 실기기 검증을 분리한다.
4. Phase 5 표시/테마/레이아웃·멀티 모니터를 완성한다.
5. Phase 6에서 카탈로그 ID별 구현·테스트·Windows 11 실행 증거를 연결한다.
6. Phase 7 패키지 확장, Phase 8 DeepSeek/Zen 정리.

Phase를 닫을 때는 `task-breakdown.md`, `traceability.md`, `original-feature-catalog.md`의 세 상태를 같이 갱신한다. 구현됐다는 이유만으로 수용 검증을 `RUN_PASS`로 바꾸지 않는다.
